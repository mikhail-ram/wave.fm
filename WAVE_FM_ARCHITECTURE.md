# Wave.fm (Antigravity Codebase Reference)

Wave.fm is an experimental, spatial music-discovery application that models a collection of songs as a mathematically continuous, searchable 1024-dimensional galaxy.

This document serves as the absolute "Source of Truth" for any developer stepping into the project. It requires zero prior context.

---

## 1. The Core Architecture (Backend & Frontend)
The project is strictly separated into a pure-functional Python backend (FastAPI) and a strictly-typed React frontend (Vite/TypeScript). 

### The Backend (`backend/`)
The backend is designed using functional programming principles. It exclusively uses pure, stateless functions documented with Google-style docstrings and strict Python type hints.

*   `server.py`: The FastAPI entry point. Defines REST endpoints (`/api/recommend`, `/api/interpolate`, `/api/graph`). It orchestrates logic but contains no heavy mathematics itself.
*   `core/db.py`: The database connection manager. Instantiates the persistent ChromaDB connection for `audio` and `lyrics` collections.
*   `core/utils.py`: Pure helper functions for database querying (`get_single_embedding`) and mathematical operations (`dot_product`).
*   `core/recommend.py`: Implements "Early Fusion" nearest-neighbor search. Used for finding similar tracks in the Discover tab.
*   `core/pathfind.py`: Implements "Geodesic Pathfinding" (Dijkstra/A*). Used for finding the smoothest musical bridges between two tracks in the Interpolate tab.
*   `core/graph_data.py`: Pre-calculates the local topological neighborhood (k-NN graph) of the entire database, which is served to the frontend physics engine.
*   `scripts/`: Contains the heavy ingestion pipeline (`ingest.py`, `compute_capitals.py`) for scraping and embedding YouTube audio and lyrics.
*   `tests/`: A comprehensive `pytest` suite ensuring the pure mathematical functions in `core/` operate flawlessly.

### The Frontend (`frontend/`)
A React application written entirely in strict TypeScript (`any` is banned).

*   `src/App.tsx` & `src/pages/Index.tsx`: The primary state orchestration files.
*   `src/components/GraphCanvas.tsx`: The heart of the visual UI. It takes the topological graph generated by `graph_data.py` and feeds it into `react-force-graph` to draw the 2D constellation map on an HTML5 Canvas.
*   `src/lib/expeditionState.ts`: A strict, pure Reducer function that manages all complex UI interactions (Hover, Click, Double-Click) across various modes (Discover, Interpolate).

## 2. The Mathematics (The 1024-D Latent Space)
Every song in the database is passed through the `MuQ-MuLan` AI model and converted into a 1,024-dimensional vector coordinate. 
*   **Audio Vectors:** Describe the sonic characteristics (tempo, instruments, genre).
*   **Text Vectors:** Describe the semantic meaning (lyrics, themes, mood).

### The Gravity Slider & "Early Fusion"
When the user adjusts the `[AUDIO <----> LYRICS]` slider on the UI, the frontend passes an `audio_weight` float (from 0.0 to 1.0) to the backend.
The backend performs **Early Fusion**: It mathematically interpolates the Audio Vector and the Text Vector into a single, unified "Hybrid Vector". 

By calculating the Hybrid Vector *before* performing any searches or geometry (Early Fusion), we guarantee that every resulting calculation is mathematically pure and perfectly balanced to the user's preference. (We explicitly avoid "Late Fusion"—which averages two separate search results together—because it is inaccurate).

## 3. The Algorithms

### A. The Constellation Map (k-NN Graph Topology)
**File:** `backend/core/graph_data.py`
To draw the spatial universe on the screen, the backend calculates the physical distance between every single song using the Hybrid Vector. It finds the 5 closest neighbors for each song and generates "edges" connecting them. The frontend physics engine treats these edges like springs, naturally clustering similar songs together into beautiful "galaxies" (e.g. Rap in one corner, Country in another) without producing a messy, tangled hairball.

### B. Discover Mode (Nearest Neighbor Search)
**File:** `backend/core/recommend.py`
When a user targets a song in Discover Mode, the backend simply finds the absolute closest neighbors to that song's Hybrid Vector. It maintains a strict `history` log to prevent the autoplay system from bouncing back and forth between two similar songs (Ping-Pong Effect).

### C. Interpolate Mode (Geodesic Pathfinding)
**File:** `backend/core/pathfind.py`
When a user asks to travel from a Country song to a Rap song, we must find a bridge of intermediate songs that slowly morph genres.
Instead of drawing a mathematically straight line through the 1024-D space (which often cuts through empty voids and grabs weird, jarring songs), we use Dijkstra's Algorithm (A* Search) to strictly "walk" across the exact same 5-neighbor topological edges used to draw the Constellation Map. 
This guarantees the transition hops cleanly from distinct cluster to distinct cluster (Country -> Folk -> Acoustic Pop -> R&B -> Rap) and guarantees the drawn path on the UI will never tangle or cross itself.

## 4. The Interaction State Machine
**File:** `frontend/src/lib/expeditionState.ts`
The UI uses Apple's "Progressive Disclosure of Intent":
*   **Hover ("Peek"):** Reveals metadata, zero commitment.
*   **Single-Click ("Target"):** Low commitment. Moves the crosshair and primes the target, but does not interrupt currently playing music.
*   **Double-Click ("Execute"):** High commitment. Instantly teleports the ship, interrupts the music, and begins playback of the new song. If Double-Clicking an off-path node during an active Interpolate journey, it triggers an "Emergency Eject", shattering the route and returning the user to Discover Mode. 

All interaction edge cases are thoroughly mapped and tested via strict headless reducers.
